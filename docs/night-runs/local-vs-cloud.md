## Findings (honest)

- **Cloud (gpt-5.4, low effort) is best on every task** and the fastest: 4-5 s per call, 9.5-9.7/10 on checks, 8.8/10 on drafts, 15/15 time-limit statuses right. (Caveat: the judge is the same model family as the cloud contestant, which may favour it.)
- **Qwen3 8B without thinking** is 1.5-2.5x slower (6-11 s) and loses 1-2 points. Never blamed anyone (0 of 39 outputs), no JSON failures or retries in 39 calls. Its weak spots: it drops instructions (the guideline paragraph) and it **missed the 12-month backstop in 3 of 3** runs of the hard date case (said "within" for a July 2025 event).
- **Qwen3 8B with thinking** fixes the date case (3/3 "outside") but takes 40-70 s and ~1,000 output tokens per call; overall 8/9 statuses right (one "close" instead of "within"). It does not help the draft (6.7 vs 6.8).
- **LFM2 2.6B is not usable here**: invents facts in 38 of 39 outputs, implies fault in 6 of 12 complaint drafts, 7/15 time-limit statuses right. And it is **not faster** on this Mac (5.8-10.8 s; Ollama runs it on the older llama.cpp runner).
- Local calls were 0 bytes to the cloud and 0 cloud tokens; token counts in and out are similar to the cloud's (Qwen writes shorter drafts: ~200 vs ~355 output tokens).

## Recommended split (now the default in `lib/agent/llm.ts`, `modelFor`)

| Work | Data | Model |
|---|---|---|
| Planner, page reading, discovery, lawyers (Elliot, Robin, Kit's page reading) | place / public pages | cloud (unchanged) |
| `compareCare`, complaint drafts, ombudsman text, enquiry draft | health + identity | `local:qwen3:8b`, no thinking (`PRIVATE_MODEL`), plus code checks (guideline quote) |
| Time-limit date reasoning (`judgeTimeLimit`, the generic complaint's `time_limit`) | health timeline | `local:qwen3:8b` **with thinking** (`modelFor("reason")`), ~45 s; better still: do the date arithmetic in code |
| Questionnaire answer -> page option (`questionnaire_choice`) | money answers | `local:qwen3:8b` (`PRIVATE_CHECK_MODEL`); not benchmarked |
| LFM2 | — | not used |

`LOCAL_MODELS=0` sends everything to the cloud (the user's OK). If Ollama is down, calls with health, money or identity data **throw** instead of going to the cloud; calls without them fall back to the cloud and say so in the log.
